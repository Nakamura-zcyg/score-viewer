# Score Viewer

ピアノ演奏用の PDF 楽譜ビューア（PWA）。Android 7.1.1 の Chrome 119 で動くことを下限に設計。

- 配信先: https://nakamura-zcyg.github.io/score-viewer/
- リポジトリ: https://github.com/Nakamura-zcyg/score-viewer

## 操作

| 操作 | 動作 |
|---|---|
| ページモード: 画面右半分をタップ | 次のページ |
| ページモード: 画面左半分をタップ | 前のページ |
| 半ページモード: 画面下半分をタップ | 次（同ページの下半分、または次ページの上半分） |
| 半ページモード: 画面上半分をタップ | 前 |
| 横幅いっぱいモード | ページ幅を画面幅に合わせる。縦にはみ出す場合は上下タップ、収まる場合は左右タップ |
| 自動スクロールモード | ページを縦に並べて一定速度で下へ流す。上半分タップで 5 秒戻し、下半分タップで 5 秒送り、2 本指タップ（PC は右クリック、タッチパッドの 2 本指タップも右クリックとして届く）で再生／停止、ドラッグで位置合わせ、長押しでメニュー |
| 長押し (既定 500ms、設定で変更可) | メニュー（ページ選択・繰りモード・全画面・ライブラリへ戻る） |
| Bluetooth ペダル／キーボード | PageDown・→・↓・Space・Enter で次、PageUp・←・↑・Backspace で前 |
| Android の戻るボタン | ライブラリへ戻る |
| ライブラリの名前変更アイコン（入力カーソル） | 表示名を変更（ファイル名とは独立） |
| ライブラリの検索欄 | 名前で絞り込み。全角半角・大文字小文字は区別しない |
| ライブラリの並び順 | 名前順（既定）／追加日順／最近開いた順。選択は端末に保存 |
| ライブラリの PDF／動画トグル | 一覧に含める種類を切り替える。両方オフにはならない |
| ライブラリの歯車 | 設定画面 |

タップは指を離した時点で判定する（押下 400ms 未満・移動 12px 未満）。長押し中はページが動かない。

繰りモードはメニューで「自動／ページ全体／半ページ／横幅いっぱい／自動スクロール」を選べる。自動は横向きなら半ページ、縦向きならページ全体。タップの向きは表示が縦に分割されているかで決まる。分割ありなら上下、なしなら左右。

半ページモードでは、上下それぞれがページ高さの 57.5% を表示する（15% の重なり、設定画面で変更可）。ちょうど半分で割ると段が上下に分断されるため。画面が極端に横長で 2 分割に収まらない場合は自動で 3 分割以上になる。レイアウトは 1 ページ目の寸法で決めるので、ページごとに寸法が違う PDF ではずれる。

## 自動スクロール

- 速度は px/秒。メニューのスライダーと ± ボタン（1.15 倍ずつ）、キーボードの ↑↓ で変えられる。Space で再生／停止、PageUp/PageDown でページ先頭へジャンプ
- 上下タップの送り／戻しは「速度 × 5 秒」分を 0.25 秒で滑らかに動かす。再生中でも合成されるので、流れを止めずに位置をずらせる。秒数は設定画面で変えられる。1 本指タップは離した時点で判定するので、2 本指判定のための遅延はない
- 速度は曲ごとに記憶し、新しい曲を開いた時は最後に使った速度が初期値になる
- 終端に達したら止まる
- 描画は毎フレーム canvas を描き直すのではなく、ページを縦に並べた帯を CSS transform で動かす。古い端末でも GPU 側だけで滑らかに動く。見えている前後のページだけ描画する
- テンポは曲中で変わるので、一定速度は「合わないところで指で直す」前提。ドラッグで位置を直せる
- 余白カット（既定で自動）: 初めてスクロールモードで開いた時に全ページを小さく描いて、暗い画素のある最初と最後の行を探し、上下の白い余白を切って並べる。ページ間は内容の前後 1.5% ずつの余白だけになり、ページをまたぐ段間が曲中の段間に近づく。結果は曲に保存する。残す余白の割合は設定画面で変えられる。メニューの「余白カット」で「なし」にすると元のページをそのまま並べる（ページ間 8px）。切り替えても同じページ内の同じ位置に留まる

## 画面消灯

楽譜と動画を開いている間は画面を消灯させない（Screen Wake Lock）。ただし設定の分数（既定 10 分）タッチもキー操作もなければ解除して端末のスリープに任せる。自動スクロールが動いている間は無操作に数えない。動画の再生中はブラウザ自体が画面を保つ。

## 設定画面

ライブラリ右上の歯車から開く。値はこの端末に保存され、開いている楽譜にも即時反映される。「既定に戻す」で全部戻る。

| 項目 | 既定 | 意味 |
|---|---|---|
| 画面消灯までの無操作時間 | 10 分 | 自動スクロール中は無操作に数えない |
| 上下タップで送る量 | 5 秒 | 自動スクロールの速度 × この秒数ぶん動く |
| 長押しの判定時間 | 500 ms | これより長く押すとメニュー |
| 半ページの重なり | 15 % | 0 でちょうど半分ずつ |
| 余白カットで残す余白 | 1.5 % | ページ高さに対する割合 |

## ライブラリの表示切替

検索欄の右に PDF と動画のトグルがある。片方だけ表示にできるが、両方オフにはならない（最後の 1 つを消そうとしても変わらない）。選択は端末に保存。

## オフライン

- 一度開けば、以後はネットなしで起動できる。Service Worker が index.html・JS・CSS・PDF ワーカー・manifest・アイコンを precache する。取り込んだ PDF は IndexedDB にあるので、開く・めくる・自動スクロールはすべてオフラインで動く
- 初回のキャッシュが終わると「オフラインでも使えるようになりました」と表示する
- 起動時に `navigator.storage.persist()` を要求し、空き容量の逼迫時に Chrome が楽譜データを追い出さないようにする。ホーム画面に追加済みなら Chrome は自動で許可する
- オフラインで動かないのは Drive のアップロード／ダウンロードだけ。押すと「Google のスクリプトを読み込めませんでした」と出る
- 新しい版は、ネットに繋がった状態で起動した時に裏で取り込まれ、その次の起動で切り替わる
- 手元で確かめる場合: `npm run build` のあと `npm run preview` で開き、キャッシュ完了のトーストを見てからサーバーを止めて再読み込みする。`BASE_PATH` 付きでビルドした dist を `vite preview` で開くと sw.js が index.html にフォールバックして登録に失敗するので、ローカル検証はベースなしでビルドする

## YouTube 動画

ライブラリ右上の再生アイコンで YouTube の URL を貼ると、一覧に動画の項目が増える。共有リンク・通常の URL・短縮 URL・Shorts・埋め込み URL のどれでも動画 ID を取り出す。タイトルは YouTube の oEmbed から取り、取れなければ手入力。

- 開くと全画面の埋め込みプレイヤー（youtube-nocookie.com）。操作は YouTube 標準
- 上のバーに戻るボタンと再生速度（0.5〜2 倍、動画が対応する値）。× でバーを隠せる
- 速度と再生位置は動画ごとに保存し、次に開いた時に続きから始める。終わり際で閉じた場合は先頭に戻す
- 画面消灯防止は楽譜と同じ
- 投稿者が埋め込みを禁止している動画はエラーになり、「YouTube で開く」リンクを出す
- オフラインでは再生できない
- 一覧は Drive の「Score Viewer」フォルダの `videos.json` で同期する。↑ で端末の一覧を合流させ、↓ で取り込む。同じ動画は更新時刻が新しい方の名前・速度・再生位置を採るので、PC で見た続きをタブレットで再生できる。他端末で Drive の一覧から外した動画は「Drive で削除済み」と表示され、上げ直さない。削除は PDF と同じ 2 段階
- タブレット側の前提は「Chrome 119 で YouTube の Web プレイヤーが動くこと」。YouTube アプリのサポート終了とは別

## Google Drive 同期

ライブラリ右上の雲アイコンで、Google アカウントにサインインして Drive の「Score Viewer」フォルダとやり取りする。アップロードとダウンロードは別の操作で、押した時だけ動く。

| 操作 | 動作 |
|---|---|
| ↑ アップロード | ここにあって Drive にない PDF を上げる。アプリで変えた名前を Drive に反映 |
| ↓ ダウンロード | Drive にあってここにない PDF を取り込む。リンク済みの名前は Drive 側を正とする |
| 削除 | まず「この端末から削除」を確認。Drive にもあれば続けて「Drive からも削除するか」を確認 |

他の端末で Drive から消した楽譜は、この端末では「Drive で削除済み」と表示され、アップロードでは上げ直さない。残すか消すかはその端末で決める。
一つの「同期」ボタンにして未リンクを全部上げる設計だと、A で消したものを B が上げ直し、次に A が降ろす、という往復が永遠に続く（user 指摘 2026-09-06）。

想定する使い方は「PC のブラウザで PDF を追加して ↑、タブレットで ↓ して演奏」。演奏中にサインイン画面が出ることはない。

スコープは `drive.file`（このアプリが作ったファイルだけ触れる、審査不要）。そのため Drive の画面から直接フォルダに入れた PDF はアプリから見えない。追加は必ずアプリの＋経由で行う。

OAuth クライアント ID は `.env` の `VITE_GOOGLE_CLIENT_ID`。Google Cloud Console で「ウェブ アプリケーション」として作り、承認済み JavaScript 生成元に配信先と `http://localhost:5173` を登録する。API キーは不要。

タブレットのホーム画面から起動した PWA でサインインのポップアップが戻ってこない場合は、タブレットの Chrome で同じ URL を開いて操作する。保存先は PWA と共通。

## 構成

- Vite + React + TypeScript
- PDF 描画: `pdfjs-dist` の legacy build（古い Chrome 向け）。前後 2 ページを先読みしてオフスクリーン canvas に保持
- 保存: IndexedDB に PDF 本体と最後に開いたページを保存。オフラインで動く
- PWA: `vite-plugin-pwa`。ホーム画面に追加すると全画面で起動

## 開発

```bash
npm install
npm run dev      # http://localhost:5173（--host 付きなので LAN 内の実機からも開ける）
npm run build    # tsc + vite build → dist/
```

## 配信 (GitHub Pages)

1. GitHub にリポジトリを作り、`main` に push する
2. リポジトリの Settings → Pages → Source を **GitHub Actions** にする
3. push のたびに `.github/workflows/deploy.yml` がビルドして `https://<user>.github.io/<repo>/` に配信する

ベースパスはワークフロー内で `BASE_PATH=/<repo>/` として渡している。独自ドメインやルート配信にする場合は `BASE_PATH=/` にする。

Service Worker と Wake Lock は HTTPS でしか動かない。`npm run dev` を LAN で開く場合はこれらが無効になるが、ページ繰り自体は動く。

## 実機で使う

1. Android の Chrome で配信 URL を開く
2. メニュー →「ホーム画面に追加」
3. ホーム画面のアイコンから起動すると、ブラウザ UI なしの全画面で開く
4. 「PDF を追加」で端末内の PDF を取り込む（取り込んだ後はオフラインで開ける）
